Topic 1 • Rosen Section 3.1

What is an Algorithm?

Formal definitions, the seven canonical properties, structured pseudocode representation, and the fundamental boundaries of mechanical computability.

Mechanical Computation and Formal Definition

The term algorithm originates etymologically from the Latinized name of the 9th-century Persian mathematician Muḥammad ibn Mūsā al-Khwārizmī, whose foundational treatise on algebraic manipulation established systematic rules for arithmetic calculation. In modern theoretical computer science, an algorithm abstracts away concrete hardware and physical execution time, functioning as a deterministic state-transition procedure.

Rosen's Formal Definition (Section 3.1):
"An algorithm is a finite sequence of precise instructions for solving a problem or performing a computation."

The Seven Fundamental Properties

To qualify as a valid algorithm under Kenneth H. Rosen's framework, every computational procedure must strictly adhere to the following seven criteria (click any property to view formal specification):

1. Input Domain Bound
▾
An algorithm must possess specified input values drawn from a clearly bounded, well-defined mathematical domain. Pre-conditions dictate the valid range of input configurations.
2. Output Range Mapping
▾
For each admissible set of inputs, the algorithm must produce output values from a specified solution domain. The output represents the formal response to the computational problem.
3. Definiteness Unambiguity
▾
Every step must be precisely, rigorously, and unambiguously defined. Determinism dictates that given identical internal states and inputs, every transition is uniquely determined.
4. Correctness Total Invariance
▾
The procedure must produce the correct output for every valid input instance. Correctness encompasses both partial correctness (invariants hold) and termination.
5. Finiteness Guaranteed Halting
▾
For any valid input drawn from the domain, the algorithm must terminate after a finite sequence of computational steps. An infinite loop is a process, not an algorithm.
6. Effectiveness Feasibility
▾
Each step must be sufficiently elementary that it can be carried out exactly and in a finite period by a human agent with paper and pencil or an idealized finite-state automaton.
7. Generality Class Parameterization
▾
The algorithm must apply broadly to all instances of a general problem class, rather than being tailored exclusively to solve a single isolated data set.
ⓘ Academic Context
Kenneth H. Rosen emphasizes that algorithms must be studied independent of hardware architectures. While hardware clock frequencies and compiler optimizations vary, asymptotic bounds remain universal.
⚠ Supplementary Concept: Halting Problem
Alan Turing (1936) demonstrated that not all computational problems are algorithmically solvable. By constructing a diagonal contradiction $K(K)$, Turing proved that no general algorithm can decide whether an arbitrary program $P$ halts on input $d$.
☑ Loop Invariant Verification
For Algorithm 1 ($\text{Max}$), correctness is formally established via induction on the invariant:
$\text{max\_val} = \max(a_1, \dots, a_i)$ after step $i$.

The Greedy Paradigm: Cashier's Algorithm

The greedy approach makes locally optimal choices at each step. Examine when greedy choice yields the global optimum and where non-canonical currencies cause it to fail.

Interactive Coin-Change Sandbox

Enter a target change amount and toggle between Canonical Currency (United States coinage: 25¢, 10¢, 5¢, 1¢) and an Arbitrary Denomination Set (Coins: 4¢, 3¢, 1¢).

Canonical US System (25, 10, 5, 1)

Greedy choice is mathematically guaranteed to be globally optimal.

Arbitrary System (4, 3, 1)

Greedy choice fails on amount = 6¢ (Greedy takes 3 coins; Optimal takes 2).

◆ Optimality Proof Sketch (Rosen 3.1)
In US currency, an optimal solution cannot contain:
  • ≥ 5 pennies (replaceable by 1 nickel)
  • ≥ 2 nickels (replaceable by 1 dime)
  • ≥ 3 dimes (replaceable by 1 quarter + 1 nickel)
  • 2 dimes + 1 nickel (25¢ → 1 quarter)
Thus, optimal change must greedily allocate quarters first, then dimes, then nickels, and pennies.
⚠ The Counterexample
For denominations {4, 3, 1} with amount 6¢:
• Greedy: 4 + 1 + 1 = 3 coins.
• Optimal: 3 + 3 = 2 coins.
Local greedy choice eliminates the globally superior combination.

Growth of Functions: Asymptotic Bounds Sandbox

According to Rosen Section 3.2, to prove $f(n) \in O(n^2)$, one must establish positive constants $C$ and $k$ such that $|f(n)| \le C n^2$ for all $n > k$. Use the sliders below to test candidate witness pairs:

◆ Mathematical Definitions
Big-O (Upper Bound):
$\exists C, k > 0 \text{ s.t. } |f(n)| \le C |g(n)| \ \forall n > k$.

Big-Ω (Lower Bound):
$\exists C, k > 0 \text{ s.t. } |f(n)| \ge C |g(n)| \ \forall n > k$.

Big-Θ (Tight Bound):
$f(n) \in \Theta(g(n)) \iff f(n) \in O(g(n)) \land f(n) \in \Omega(g(n))$.
ⓘ Witness Non-Uniqueness
Witnesses are never unique. For $4n^2 + 7n + 5$, both $(C=16, k=1)$ and $(C=6, k=7)$ are valid pairs.
